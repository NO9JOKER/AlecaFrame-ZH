# v1.2.0 项目计划

> 目标版本：`1.2.0`。本文描述新架构的工作流、里程碑、验收与发布清单。
> 架构决策见 [ADR 0001](../decisions/0001-capability-first-architecture.md)、[ADR 0002](../decisions/0002-contribution-and-review-model.md)。
> 可变数字以命令输出/生成报告为准，不在本文写死。

## 1. 目标

- 以单 bundle 注入为前提，建立能力优先的运行时模块：`core`、`rules`、`dom`、`features`、`adapters`。
- 页面信息集中到 `pages.json` + 生成矩阵；页面差异只放适配器例外层。
- 词典成为一等公民：manifest 决定优先级，生成物隔离，人工词条按功能屏分组，override 有 scope/reason/source。
- launcher 拆成可测试的 PowerShell 模块；页面清单与 OCR 清单来自 manifest。
- OCR 建立独立边界：`manifest`、`CONTRACT`、`page-scripts`、`server`、`worker`；逻辑保持稳定。
- 文档分层：`AGENTS.md` + 贡献者入口 + 模块 README + 文件头契约 + ADR；可推导事实由脚本生成。
- 建立 CI/复核门禁，让 fork PR 可以被维护者安全地手动合并。

## 4. 验收原则

- **行为等价优先于结构漂亮**：模块化实现与集成过程中，翻译输出、搜索行为、注入结果、快照/还原必须可验证一致；有意的行为变化单独列出。
- **数据结构变更与语义变化分开提交**：词典布局/加载方式与译名修正不混在一个 PR。
- **可机器判的进 CI**：schema、manifest、重复键、覆盖、golden、构建确定性、链接/索引、页面清单一致性。
- **必须真机的由开发者签字**：视觉布局、Overwolf 注入、游戏内 OCR、宿主升级后的 hook 行为；维护者抽检 T2。
- **失败可诊断**：错误必须指向具体文件/规则/页面，不能静默吞异常。

## 8. 残余风险

- launcher 与 OCR 涉及真实安装/可选组件，真机证据无法覆盖所有机器。
- 单人口径：没有外部用户，兼容压力小，但“唯一用户=唯一测试者”，验证不能省。
- 文档/索引若不接入 CI 检查，仍可能漂移。
- 宿主升级后 hook 方法与选择器可能失效，需要版本核对与诊断。
