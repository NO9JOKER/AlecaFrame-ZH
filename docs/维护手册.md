## 0. 先看这三句话

1. **汉化不改官方安装包**：补丁只做三件事——启动前从官方 `app.opk` 还原 10 个前端页面、带参数启动 Overwolf、在页面里注入 `alecaframe-zh-cn.js`。
2. **改文案不用重启 Overwolf**：改词库 → 跑构建 → `Refresh-Chinese.cmd` 只重载 AlecaFrame 渲染进程（约 10 秒）。改启动器/页面清单时才需要完整 `Start`。
3. **版本升级先跑自检**：`powershell -ExecutionPolicy Bypass -File scripts\test-inject.ps1`，它会只读检查真实安装里的补丁锚点是否还在。

### v1.1.0 新增模块（维护时注意）

| 模块 | 位置 | 维护要点 |
|---|---|---|
| 中文搜索 | `src/search.js` + `tests/search.test.mjs` | 改钩子后跑 `node tests/search.test.mjs`；宿主判定依据见 `docs/中文搜索原理.md` |
| 中文 OCR | `bin/ocr/` + `scripts/Install-OcrPrerequisites.ps1` | 集成契约见 `docs/OCR集成说明.md`；`bin/ocr/.tools` 不入库 |
| 词库分层 | `dict/mioeu-terms.tsv`、`dict/extra-8.tsv` | 来源与冲突见 `docs/词典来源.md`；扫描未翻译文本用 `python src/scan_missing.py` |
| 构建产物 | `bin/alecaframe-zh-cn.js`、`bin/ocr/afzh-items.js` | 均为 `python src/build.py` 生成，已 gitignore，不要手工改 |

> `build-unmatched.txt` 里的「词条在源码中找不到」大多是上游 2.x 时代淘汰文案（无害，不会命中），
> 只有当你**新增**词条后这个数字变大时才需要检查是否拼写/标点写错。
3. **最坏情况永远能恢复**：`Restore-English.cmd` 会还原官方文件并正常启动；即使补丁完全失效，也能手动用 `app.opk` 还原或重装 AlecaFrame。

### 1.2 运行原理（4 步）

```
Start-Chinese.cmd
  1) 关闭 Overwolf
  2) 从官方 app.opk 还原 10 个页面（main.html、relicOverlay.html …）
  3) 用带参方式启动 Overwolf（关闭扩展完整性校验，仅本次会话）
  4) 注入 <script src="assets/js/alecaframe-zh-cn.js"> 到页面，只重启 AlecaFrame 渲染进程
```

`alecaframe-zh-cn.js` = **词典**（约 2 万条）+ **运行时翻译层**：遍历 DOM 文本节点/属性，精确匹配英文并替换；MutationObserver 持续补翻 Vue 动态渲染出来的内容；数字/日期等模板用正则规则处理。

## 4. 维护工作流 A：修界面文案（最高频）

### 4.1 定位原文

1. 在界面上看到英文，先截图（或回忆上下文）。
2. 在应用源码里搜英文原文（注意 `web/` 是 3.0.6 的实际源码）：

```powershell
$ext = "$env:LOCALAPPDATA\Overwolf\Extensions\afmcagbpgggkpdkokjhjkllpegnadmkignlonpjm\3.0.6\web"
Select-String -Path "$ext\main_parts\*.html","$ext\assets\js\main\*.js" -Pattern "No preferences set" -SimpleMatch
```

3. 判断类型：
   - **HTML 静态文本**（`<span>Search</span>`）→ 直接加词条；
   - **JS 字符串**（`return 'No preferences set'`）→ 渲染成文本节点后同样能匹配，直接加词条；
   - **模板插值**（`{{n}} recorded days`）→ 需要正则规则（见 4.4）。

### 4.2 加词条

在 `dict/extra-6.tsv`（或新建 `extra-8.tsv`）里按 **英文<TAB>中文** 追加一行，注意：

- 必须与界面上的文本**完全一致**（大小写、标点、空格；`’` 与 `'` 不同）；
- 不要翻译纯数字/纯符号；
- 长句也可加，但只对该完整文本生效；
- 词条优先级（后者覆盖前者）：`items.tsv` → `translations.zh-CN.json`（上游）→ `fixes.tsv` → `extra-*.tsv`。
  **UI 文案一律放 extra，保证覆盖物品名里的同名冲突。**

### 4.3 构建 + 生效

```powershell
python src\build.py
```

输出 `bin\alecaframe-zh-cn.js`，并打印：

- `keys not found in app source: N` —— 说明有词条在源码里找不到（拼写/标点错，或该文案已随版本删除），可忽略旧词条，但新加的最好为 0；
- 明细在 `build-unmatched.txt`。

然后在中文会话里运行 `Refresh-Chinese.cmd`（或工作区调试：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File bin\AlecaFrame-ZH.ps1 -Action Refresh
```

），看日志 `translated=` 数字是否变化，再截图确认。

> 注意：`bin\alecaframe-zh-cn.js` 是生成物，**不要直接改**；改了也会被下次构建覆盖。

### 4.4 动态模板（数字/日期/数量前缀）

规则在 `src/engine.js` 的 `RULES` 数组里，格式：

```js
[ /^正则$/, (m, rec) => "译文" ]
```

`m[1]` 是第一个捕获组；若你把 `m[1]` 传给 `translateValue()`，会先把捕获内容再翻一遍（用于 `Last record: Nov 4, 2026` 这种嵌套）。

现有规则示例：

| 规则 | 效果 |
|---|---|
| `^(\d[\d,]*) recorded days(?: in range)?$` | `223 recorded days` → `223 天已记录` |
| `^([+-]?\d[\d,]*(?:\.\d+)?%)\s+(.+)$` | 裂罅属性整串：`+109.9% Critical Damage` → `+109.9% 暴击伤害`（属性名翻不出来则整串不动） |
| `^x(\d+(?:\.\d+)?)\s+(.+)$` | 裂罅倍率：`x1.5 Damage to Corpus` → `x1.5 对 Corpus 伤害` |
| `^Last record: (.+)$` | `Last record: Nov 4, 2026` → `最后记录：2026 年 11 月 4 日` |
| `^Rank (\d+)\/(\d+)$` | `Rank 8/8` → `等级 8/8` |
| `^(\d+)x (.+)$` | `2x Forma Blueprint` → `2 个 Forma 蓝图` |
| `^Starts at (.+)$` | `Starts at 09:00 PM` → `开始于 09:00 PM` |
| 月份规则 | `January 2026` → `2026 年 1 月`；`Nov 5` → `11 月 5 日` |

加规则时注意：

- 必须 `^...$` 全串锚定，避免误伤普通文本；
- 数字用 `\d[\d,]*(?:\.\d+)?` 兼容千分位/小数；
- 规则在词典未命中后才执行，性能影响可忽略（几十条）。
- 日历里的 `M T W T F S S` 是单字母，**不要**加单字母规则（会误伤所有单字母文本）。
- 「节点, 星球」复合文本（仲裁/入侵/裂缝里显示的 `Lares, Mercury`）不走 `RULES`，而是 `src/engine.js` 的
  `translateComposite()`：只翻逗号后的星球名，**节点名保持英文**——游戏中文客户端里节点名本来就是英文
  （中文 wiki 也写作 `水星 Lares`）。要新增/修改星球名，改 `PLANET_NAMES` 集合并确认 `dict/extra-5.tsv` 里有该译名。

### 4.5 验证

- 控制台日志：`[AlecaFrame-ZH] loaded translated=N entries=M`；
- 截图：`verify\capture.ps1`（PrintWindow 抓 AlecaFrame 窗口）；
- 自动点侧栏：`verify\click.ps1 -X 90 -Y 305 -Out xxx.png`（坐标是窗口内坐标；注意窗口边框偏移，必要时先截图试点）。这两个脚本仅调试用，**不要打进分发包**。

## 5. 维护工作流 B：物品名（武器/MOD/赋能/资源/遗物/部件）

### 5.1 数据从哪来（不需要 wiki）

AlecaFrame 自带游戏数据：`%LOCALAPPDATA%\AlecaFrame\cachedData\json\`

- 各分类表（`Mods.json`、`Primary.json`、`Melee.json`、`Arcanes.json`、`Resources.json`、`Relics.json`、`Components.json`…）：英文名 + `uniqueName`；
- `lang.json`：`uniqueName` → 14 种语言名称（含 `zh` 简体、`tc` 繁体），共 19,511 条 × 14。

`src/build_items.py` 做三件事：

1. **普通物品**：`name` + `zh(uniqueName)` 直接配对；
2. **遗物**：中英都去掉精炼后缀，得到 `Axi A1` → `后纪 A1`；
3. **部件**：`父物品中文名 + 部件中文名`，例如 `Braton Prime` + `Barrel` → `布莱顿 Prime 枪管`；
   父级是**战甲**时保留英文父名（`Wukong Prime 机体蓝图`），符合“战甲名不汉化”的要求；
   部件缺中文时用 `PART_ZH` 手工表补（Blueprint→蓝图、Chassis→机体…）。

### 5.2 重新生成

```powershell
python src\build_items.py   # 重新生成 dict\items.tsv
python src\build.py         # 合并进 bin\alecaframe-zh-cn.js
```

然后 `Refresh-Chinese.cmd`。

### 5.3 新增/修正物品名

- **官方缺中文名**：在 `build_items.py` 的 `MANUAL` 字典里加 `"英文名": "中文名"`（例如 Forma 蓝图、Orokin 催化剂）；
- **部件词缺失**：在 `PART_ZH` 里补（如 `"Wiring": "线路"`）；
- **个别覆盖**：也可以直接在 `dict/extra-*.tsv` 里写同名条目，UI 词条优先级更高。

### 5.4 已知注意点

- 名称冲突（同一英文名对应不同中文）时脚本保留**先出现的**，并在输出打印 `CONFLICT`；确认无关键冲突即可。
- 战甲名（`Warframes.json`）**故意不映射**；如果你以后想汉化战甲，只需在 `build_items.py` 的文件列表里加上 `Warframes` 并去掉父级跳过逻辑。
- 物品名不会翻译“节点名/裂罅生成名/阵营名”，这些在游戏数据里本来就没有中文。

## 6. 维护工作流 C：AlecaFrame / Overwolf 更新后

### 6.1 更新后的典型现象

| 现象 | 说明 |
|---|---|
| 界面变回英文 | 扩展目录换了新版本，补丁文件还在旧版本目录 |
| AlecaFrame 打不开/闪退 | 新版本页面被改 + 校验拦截；或需要重新 Start |
| 部分页面空白/错位 | 页面结构变了，注入脚本仍在但选择器/模板变了 |
| 日志 `HashMismatch` | Overwolf 校验没被参数降级（客户端行为变了） |

### 6.2 处理顺序（每次更新都按这个来）

1. **查版本**：

```powershell
Get-ChildItem "$env:LOCALAPPDATA\Overwolf\Extensions\afmcagbpgggkpdkokjhjkllpegnadmkignlonpjm" -Directory
Get-Content "$env:LOCALAPPDATA\Overwolf\Extensions\afmcagbpgggkpdkokjhjkllpegnadmkignlonpjm\3.0.x\manifest.json" -TotalCount 8
```

2. **运行一次 Start**：脚本会自动选“最新版本目录”，并从该版本 `app.opk` 还原官方页面。多数小版本更新（只改文案/资源）到这一步就恢复了。
3. **看日志**：`logs\launcher.log` + `MainWindow.html.log`。
   - 成功：`[AlecaFrame-ZH] loaded translated=...`
   - 失败：日志会说明是“未能加载”还是“打不开”，并自动还原官方文件。
4. **检查页面清单**（大版本更新时）：
   - 官方 manifest 的 `data.windows` 里有哪些 `file`；
   - 启动器 `$Pages` 列表（`bin\AlecaFrame-ZH.ps1` 顶部）；
   - 若官方新增页面，把新页面加进 `$Pages`，否则新页面不汉化（不影响使用）。
5. **检查 Overwolf 启动参数是否仍有效**：
   - 正常：`Status.cmd` 显示“本次会话已带校验绕过参数: True”且 app 能加载；
   - 若 `Start` 失败并出现 `Closing extension … HashMismatch`：说明 Overwolf 改了校验实现。
     - 历史：0.305 只需 `--ow-disable-features=extension-validation,read-opk-from-memory`；0.311 起需要再加 `--ow-enable-features=force-validation-report-only`。
     - 排查：在 Overwolf 安装目录的 `Overwolf.Extensions.dll` 里搜 feature 名称（UTF-16 字符串），确认参数名是否还存在；参考社区项目 [MIOEU/AlecaFrame-ZH PR#3](https://github.com/MIOEU/AlecaFrame-ZH/pull/3)。
6. **回归检查**：至少看 6 个页面——铸造厂、遗物规划、裂罅、统计、设置、两个叠加层（遗物奖励/紫晶重洗，需要游戏内）。
7. **重新打包分发**（见第 9 节）。

### 6.3 如果页面结构变了

- 打开新版本 `web/` 下对应 HTML，对比注入点 `</body>` 是否还在（一般在）；
- 检查页面里的类名/模板是否变化（例如原来 `v-for` 的 key 改了），涉及深度注入的功能（如未来的 OCR 脚本）需要单独适配；
- 词典法的好处是**大部分文案变化只影响词条**，页面骨架变化才需要改代码。

## 7. 故障排查手册

| 症状 | 排查 | 处理 |
|---|---|---|
| Start 后仍是英文 | `logs\launcher.log`；`Status.cmd`；`MainWindow.html.log` 是否有 `[AlecaFrame-ZH] loaded` | 重新 Start；确认扩展目录里有 `assets/js/alecaframe-zh-cn.js` |
| app 打不开/反复闪退 | `Trace_*.log` 搜 `Closing extension` | 运行 Restore；再 Start；仍不行检查 Overwolf 版本/参数 |
| `HashMismatch` | 同上 | 说明校验未被降级：确认启动参数包含两个 flag；确认 Overwolf 启动的确是我们起的进程（不是用户手动开的） |
| 中文显示方块 | 系统字体 | 一般 Windows 自带微软雅黑；远程桌面/精简系统装中文字体 |
| 某页中文但布局错乱 | 中文比英文长 | 该页 CSS 固定宽度导致；临时可在 extra 词条里用更短译名 |
| 改了词条不生效 | 忘 build？忘 Refresh？token 覆盖？ | 依次 `build.py` → `Refresh`；看日志 entries 是否变化 |
| Restore 后还是中文 | 文件未还原（opk 缺/权限） | 看 launcher.log；手动用 `app.opk` 解压覆盖；或重装 AlecaFrame |
| 开机后 AlecaFrame 打不开 | Overwolf 以普通模式自启，而文件仍是补丁版 | 运行 Start（会先还原再带参启动）或 Restore |
| 词库构建报 `keys not found` 很多 | 上游旧词条 | 只关心新加词条；旧词条可逐步清理 |
| Python 不在 PATH | 用完整路径 | 安装 Python 3 后 `python src\build.py` |

日志速查：

- 成功标记：`[AlecaFrame-ZH] loaded translated=N entries=M`
- 注入标记：`[AFCN] injected test OK`（仅测试用）
- 启动器日志：`[时间] 已还原官方文件（来源：opk）` / `中文界面加载成功（版本 x.y.z）`

## 8. 备份、回滚与合规

### 8.1 备份（本机已有）

- `backup\ext-3.0.6\`：完整官方扩展目录拷贝；
- `backup\opk-3.0.6\`：官方 opk 解压内容；
- 运行时快照：`state\official\<版本>\web\*.html`（只含 10 个页面，首次 Start 生成）。

**最关键的是 `PackagesCache\<appId>\<版本>\app.opk`**：只要它在，任何改动都能还原。建议升级版本后把新 opk 复制到 `backup\` 留档。

### 8.2 三层回滚

1. `Refresh-Chinese.cmd`：只重置词库脚本；
2. `Restore-English.cmd`：还原 10 个页面 + 正常启动（日常最常用）；
3. 手动终极回滚：
   ```powershell
   # 关闭 Overwolf 后，用 opk 解压覆盖 web 下被改的页面
   ```

## 9. 诊断包（排障入口）

出问题（任何一台电脑）时，让用户双击 **`导出诊断包.cmd`**，桌面会生成
`AlecaFrame-ZH-Diagnostics-<时间>.zip`。它会读取并打包：

- `env.txt`：系统 / Overwolf / AlecaFrame 版本、`app.opk` 缓存、注入状态、charset 是否补齐、
  OCR 组件与模型、`AlecaFrame-ZH.settings.json`、桌面快捷方式指向
- `status.txt`：`Status` 动作输出
- `injection.txt`：10 个页面分别注入了哪些脚本、是否声明 UTF-8
- `logs/`：`launcher.log`、`ocr-install.log`、OCR 运行日志、`last-session.json`
- `overwolf/`：Overwolf 各窗口日志尾部（含扩展加载 / HashMismatch 等校验信息）

实现：`scripts/Export-Diagnostics.ps1`（只读收集，不修改任何状态）。
`launcher.log` 超过 2 MB 会自动只保留最近 2000 行，避免无限增长。

**排障建议顺序**：`Status.cmd` → `logs\launcher.log` → 导出诊断包 → 对照 `env.txt` 的
「已注入 / charset / OCR 组件」三项定位。

中文搜索类问题优先看 `overwolf\BackGround.html.log` 里的
`[AlecaFrame-ZH] 中文搜索已加载：… 自检: 膛线→"Serration"` 这一行：
`hasChinese=false` 或 `codes` 不是 `819b,7ebf` 就是字符集问题（见 CHANGELOG v1.1.6）。
