# AlecaFrame-ZH 项目架构与实现说明

> 面向对象：接手本仓库做**代码 / 架构重构**的会话或维护者。
> 基线：AlecaFrame `3.0.6`、Overwolf `0.311.1.6`；仓库版本 `v1.1.10` + 未发布的 v1.1.11 工作区改动（源力石汉化等）。
> 代码规模（用于评估重构成本）：启动器 `bin/AlecaFrame-ZH.ps1` 911 行；`src/search.js` 1138 行；`src/engine.js` 293 行；`src/build.py` 205 行；`scripts/verify.ps1` 304 行；`tests/search.test.mjs` 550 行。
> 本文与代码不一致时**以代码为准**，并请顺手修正本文。

---

## 0. 30 秒读懂

- 这是**非官方简体中文补丁**，不是 AlecaFrame 的分支：仓库里没有任何 AlejcaFrame 源码。
- 实现方式：启动器用参数关闭 Overwolf 扩展校验，启动后向 AlecaFrame 的网页（10 个 html 页面）注入一个 JS 文件 `bin/alecaframe-zh-cn.js`，该文件由「词典 JSON + 翻译层 engine.js + 中文搜索 search.js」拼成。
- 翻译是**运行时 DOM 精确文本匹配**（不 hook 业务逻辑、不改打包文件）；中文搜索是**插件方法包装 + 本地过滤**。
- 词典是分层的 TSV（约 2.5 万条），构建脚本按固定优先级合并；发布走 GitHub Actions，tag `v*` 自动出 zip。
- 可选 OCR 子系统（移植自 MIOEU）用于中文界面下的遗物/裂罅识别，默认不装也能用。

## 1. 项目定位与硬约束

### 1.1 是什么

| 项 | 说明 |
|---|---|
| 目标 | 让 Overwolf 应用 AlecaFrame 在**中文游戏语言**下可用：界面中文、物品中文、中文搜索、OCR 增强 |
| 手段 | 运行时注入 JS + 词典；Open Overwolf 时传校验绕过参数 |
| 平台 | Windows + PowerShell 5.1；Overwolf 扩展机制（`%LOCALAPPDATA%\Overwolf\Extensions\<appId>\<version>`） |
| 基线版本 | AlecaFrame 3.0.6 / Overwolf 0.311.1.6 |

### 1.2 硬约束（重构时不要破坏）

1. **不修改官方安装包的签名/DLL**。唯一的“原位改写”是 OCR 相关的两个官方前端文件（见 8.3），且启动器会先备份、可一键还原。
2. **注入必须可逆**：所有改动前先 `Save-OfficialSnapshot` 落到 `state/official/<版本>/`，Restore/Start 都会从快照或官方 `app.opk` 还原。
3. **PowerShell 脚本必须 UTF-8 with BOM**（Windows PowerShell 5.1 读中文必需），CI 有检查；v1.1.7 曾因丢 BOM 导致 CI 红 + 用户端解析报错。
4. **构建产物不入库**：`bin/alecaframe-zh-cn.js`、`bin/ocr/afzh-items.js` 在 `.gitignore`，发布包由构建步骤生成。
5. **兼容 MIOEU 的 OCR 协议**：OCR 服务在 `127.0.0.1:38147`，全局名 `__ALECAFRAME_ZH_CN_*`；`build.py` 额外输出 `window.__ALECAFRAME_ZH_CN_ITEMS__` 兼容层，不要删。

## 2. 运行时全景

```
用户双击 Start-Chinese.cmd
  └─ powershell -File bin\AlecaFrame-ZH.ps1 -Action Start
       1) 关闭 Overwolf（Stop-Overwolf）
       2) 定位 Overwolf 根目录 / 扩展版本目录（Get-OverwolfVersionDir → Get-AppVersionDir）
       3) 从官方 app.opk 还原 10 个页面 + 1 个官方脚本（Restore-OfficialFiles / Save-OfficialSnapshot）
       4) 带校验绕过参数启动 Overwolf（Start-Overwolf）
            --ow-disable-features=extension-validation,read-opk-from-memory
            --ow-enable-features=force-validation-report-only
       5) 把 bin\alecaframe-zh-cn.js 复制到 web\assets\js\，并向 10 个页面插入
          <script src="assets/js/alecaframe-zh-cn.js"></script>（Apply-Patch / Add-ScriptTag）
       6) 等插件/renderer 就绪（Wait-ZhLoaded / Test-Patched），失败则自动还原
       7) 若开启 OCR：启动本地 OCR 服务、复制并注入 OCR 脚本、对 2 个官方文件打补丁
       8) 记录 state\last-session.json、写 logs\launcher.log

页面内：
  <script src="assets/js/alecaframe-zh-cn.js">
    = window.__AFCN_DICT__（词典 JSON）
    + window.__AFCN_RELIC_REWARDS__（遗物→奖励文本，中文模糊搜索用）
    + window.__ALECAFRAME_ZH_CN_ITEMS__ = 同一份词典（OCR 兼容）
    + engine.js   （DOM 文本/属性精确翻译 + MutationObserver）
    + search.js   （中文搜索：插件方法包装 + 应用级钩子 + 诊断）
```

**窗口差异**：AlecaFrame 有两个主要页面窗口——`main.html`（主界面）和 `background.html`（后台）。`plugin.get()` 返回的 C# 插件对象**每个窗口各自一份**，钩子必须各自安装。`src/search.js` 里的 `whenPluginReady()` 是两窗口共用入口，内部通过 `status.window` 区分（`document.getElementById("tabInventory")` 存在即 main）。

### 3.3 `dict/`（词典层，构建时合并）

| 文件 | 条数* | 来源/作用 |
|---|---|---|
| `items.tsv` | 18778 | `src/build_items.py` 从本机 AlecaFrame 游戏数据生成：物品/部件/遗物/资源等官方简中名（权威，优先级最高的一层是**先写入**，但会被后续层覆盖同键） |

\* 条数以 `Get-Content ... | Measure` 为准，会随版本变化。

各 `extra-*` 的主题（按现状，重构时可重新分组）：
`extra-1/2/3/4` UI 文案补漏；`extra-5` 星球/地点/天气等世界状态词；`extra-6/7` 物品/属性/裂罅早期补漏；`extra-8` 大规模 UI 文案（1000+ 行，主要维护文件）；`extra-9` 零星；`extra-10` WFM/界面；`extra-11` 裂罅属性名（含熔接词条）+ WFM 短名；`extra-12` 执刑官源力石效果/名称/颜色/特性。

**合并优先级（低→高）**：`items` → `mioeu` → `vendor/translations.zh-CN.json` → `fixes` → `extra-*`（数字升序）。
即：**任何 `extra-*.tsv` 都能覆盖前面所有层**；改词最稳的做法是加到编号最大的 extra 或新建 `extra-13`。

## 4. 启动器（`bin/AlecaFrame-ZH.ps1`）详解

### 4.1 参数与动作

```
param(
  [ValidateSet("Start","Restore","Toggle","Status","InstallShortcuts","Refresh","OcrOn","OcrOff","InstallOcr")]
  [string]$Action = "Status",
  [switch]$NoGui
)
```

| Action | 行为 |
|---|---|
| `Start` | 停 Overwolf → 还原官方文件 → 带 flag 启动 → 注入 bundle → 等注入生效 →（可选）OCR → 记录状态 |
| `Restore` | 停 Overwolf → 还原官方文件 → 正常启动 Overwolf（不带 flag） |
| `Toggle` | 仅在**带 flag 的会话**里：已注入则还原页面，未注入则注入；只 `Restart-AlecaFrameRenderer`，不重启 Overwolf |
| `Refresh` | 中文会话内：重新复制最新 bundle、重新注入、重载渲染进程（改完词典/代码用） |
| `Status` | 打印：是否带参会话（`Test-FlaggedSession`）、注入页面列表、OCR 状态、版本号 |
| `OcrOn/OcrOff` | 设置 `AlecaFrame-ZH.settings.json` 并启停 OCR helper / 注入 OCR 脚本 |
| `InstallOcr` | 调 `scripts/Install-OcrPrerequisites.ps1` 下载 OCR 依赖 |
| `InstallShortcuts` | 桌面快捷方式（Start/Restore/Toggle） |

### 4.2 关键常量（重构时注意这些是被硬编码的契约）

```powershell

$script:Pages = @("main.html","AFBuilds.html","InGameNotification.html","relicOverlay.html",

                     "--ow-enable-features=force-validation-report-only")
$script:OcrScripts = @(... 9 个 afzh-*.js ...)
$script:OcrInjections = @(
  @{ Page="background.html";          Scripts=@("afzh-relic-ocr.js","afzh-riven-ocr.js") },
  @{ Page="rivenOverlay.html";        Scripts=@("afzh-riven-overlay.js") },

  @{ Page="relicRecommendation.html"; Scripts=@("afzh-relic-recommendation.js") },
```

### 4.3 Start 流程（`Invoke-StartChinese`）

1. `Stop-Overwolf`：结束 Overwolf 进程（避免文件占用/页面被缓存）。
2. `Find-OverwolfRoot` / `Get-OverwolfVersionDir` / `Get-AppVersionDir`：定位 `%LOCALAPPDATA%\Overwolf`、扩展 `afmcagbpgggkpdkokjhjkllpegnadmkignlonpjm\<版本>`；版本目录按 `manifest.json` 存在 + 版本号数字比较选择。
3. `Get-OfficialSource`：优先从 `PackagesCache` 的 `app.opk` 取官方页面树；没有 opk 则从已安装扩展目录取。
4. `Save-OfficialSnapshot` → `state/official/<appVersion>/`（保存原始页面和 `assets/js/relicOverlay/main.js`）；若已有快照且文件 pristine 则复用。
5. `Restore-OfficialFiles`：把快照写回扩展目录（保证每次 Start 都从官方文件开始，幂等）。
6. `Start-Overwolf`：带 `$script:FlagArgs` 启动 Overwolf 主程序；`Wait-ExtensionLoaded` 等扩展加载。
7. `Copy-Item bin\alecaframe-zh-cn.js → web\assets\js\alecaframe-zh-cn.js`。
8. `Apply-Patch`：对 10 个页面 `Add-ScriptTag`（幂等：已存在则跳过；页面缺 `</body>` 等锚点时报警）。
9. `Restart-AlecaFrameRenderer` 重载 AlecaFrame 渲染进程；`Wait-ZhLoaded` 轮询日志/页面确认脚本加载（超时 → 自动 `Restore-OfficialFiles` 并抛错）。
10. `Test-FlaggedSession` 校验当前 Overwolf 会话确实是带参启动（否则 Toggle 等行为不生效）。
11. 若 OCR 开启：`Start-OcrHelper`（本地 38147 服务，日志 `state\RelicChineseOcr\helper.{out,err}.log`）→ `Apply-OcrPatch`（复制 9 个 OCR 脚本、注入对应页面、`Patch-RelicOverlayMain` 替换官方 `main.js` 的奖励回退、`Patch-RivenOverlayHtml` 给 `rivenOverlay.html` 的循环加 `:key`）。
12. `Save-State`：写 `state\last-session.json`（带参会话标记、注入页面、OCR 开关等），写 `logs\launcher.log`。

### 4.4 注入算法（`Add-ScriptTag` / `Apply-Patch`）

- 目标页面文本里查找 `</body>`（或页面特定的最后 `</script>` 锚点），在末尾插入 `<script src="assets/js/alecaframe-zh-cn.js"></script>`；

- `Test-Patched`：检查 10 个页面是否都含脚本标签 / 或都还原成功；
- 页面编码：插入前确保文件声明 UTF-8（`charset` 检查在 `Status` 里报告）。

### 4.5 快照/还原（`Save-OfficialSnapshot` / `Restore-OfficialFiles` / `Test-CurrentFilesPristine`）

- 快照路径：`state\official\<appVersion>\`，只保存被我们改动的文件（页面的原始 html + `relicOverlay/main.js`）；
- 还原时对比当前文件与快照，一律覆盖（幂等）；`Test-CurrentFilesPristine` 判断当前是否官方原样（未注入/未打 OCR 补丁）；
- **升级兼容**：AlecaFrame 小版本更新会新建 `<version>` 目录，每次 Start 会重新取快照，旧快照保留但不再使用。

### 4.6 Toggle / Refresh / Status 的差异

| | 重启 Overwolf | 还原官方页面 | 重新复制 bundle | 重新注入 | 适用 |
|---|---|---|---|---|---|
| Start | 是 | 是 | 是 | 是 | 冷启动 |
| Toggle | 否 | 已注入则还原 | 否 | 未注入则注入 | 会话内中英切换 |
| Refresh | 否 | 否 | 是 | 是 | 改词典/代码后刷新 |
| Restore | 是 | 是 | 否 | 否 | 恢复英文 |

> `Refresh` 只重载 AlecaFrame 渲染进程（`Restart-AlecaFrameRenderer`），不会重启 Overwolf；这就是日常“改完词典 → Refresh 就能看到”的原因。

## 5. 运行时翻译层（`src/engine.js`，293 行）

### 5.1 词典与索引

```js
const DICT = window.__AFCN_DICT__ || {};
const map = new Map();       // 规范化英文键 -> 中文
const lowerMap = new Map();  // 纯拉丁键的小写索引（WFM 大小写不固定）
```

- 键用 `norm()` 规范化（`\s+`→空格、trim）；空键/重复键跳过；
- `lowerMap` 只收录 **不含 CJK** 的键：精确匹配失败时按小写再查一次（解决 `Status damage` vs `Status Damage`）；
- `window.__AFCN_DICT__` 保持引用（`window.__AFCN_DICT__ = DICT`），OCR 兼容层直接用它。

### 5.2 `translateValue` 决策链（严格按顺序）

```
1) 规范化后为空 / 不含 [A-Za-z]       -> null（纯数字、纯中文不处理）
2) map 精确命中                        -> 返回中文
3) 不含 CJK 时 lowerMap 小写命中       -> 返回中文
4) translateComposite()：`节点, 星球`  -> 只翻逗号后的星球名（节点保持英文）
5) applyRule()：按 RULES 顺序试正则     -> 命中返回
6) 全部失败                            -> null（保持英文）
```

### 5.3 `RULES` 规则清单（概览，按代码顺序）

| 规则 | 示例 |
|---|---|
| `% match` | `75% match` → 75% 匹配 |
| `View X shards` | 查看琥珀源力石 |
| `Tauforged X` | 深红 TAU源力石 |
| `Installed on N Warframes` | 已安装在 N 个战甲上 |
| `Copy N` | 复制 N |
| 百分比 + 属性名 | `+109.9% Critical Damage` → `+109.9% 暴击伤害`（裂罅把伤害类型补「伤害」） |
| `xN + 属性名` | `x1.5 Damage to Corpus` |
| 正负号 + 属性名（含 Unicode 负号 `− – — －`） | `+Multishot` / `-Zoom` → `-变焦` |
| Stela 融合行 | `100 Stela, 5 possible now` → `100 虚空石块，当前可用 5 次` |
| `X effects` | `Topaz effects` → 黄玉效果 |
| `Find Warframes using X` | 查找使用「…」的战甲 |
| `+N more effects` | 另有 N 种效果 |
| `N / 5 installed(, M Tauforged)` | `5 / 5 已安装，3 TAU源力石` |
| `N / 5 slots(, M Tauforged)` | 槽位写法 |
| `Last record:` / `Today,` / `Tomorrow,` / 月份日期 | 统计/日历 |
| `N recorded days` / `N recorded` / `N copies remaining` | 统计页 |
| `Rank N / M`、`MR N`、`N Endo to max`、`N credits to max`、`N mods`、`N orders`、`Nx …` 等 | 各处模板 |

> 规则是全局生效的，**写得太宽会误伤**（例如 `^(\d+) (.+)$` 这种绝不能用）。v1.1.11 的源力石「N + 效果名」因此只放在 `search.js` 的局部扫描里，不进 `RULES`。

### 5.4 裂罅上下文（`inRivenContext`）

- 判定：文本节点向上最多 8 层，祖先 `className` 含 `riven` 即视为裂罅上下文；
- 裂罅内额外处理：
  - 伤害类型词补「伤害」后缀（`火焰` → `火焰伤害`），`寒冷` 按游戏词形改 `冰冻`；
  - 纯数值 + 属性名（`+0.3 Range` → `+0.3 攻击范围`）；
  - 秒单位（`6s Combo Duration` → `6 秒连击持续时间`）；
  - 整串属性名先按普通词典翻，再补伤害后缀。
- **WFM 相似裂罅**的属性名是外部数据，大小写/短名不固定：靠 `lowerMap` + `extra-11.tsv` 的短名表兜底。

### 5.5 属性翻译

- `ATTRS = ["placeholder","title","aria-label","data-tooltip","data-tippy-content"]`；
- `translateAttrs(el)` 对属性值做 `translateValue`，命中则 `setAttribute`；
- tippy 的悬停提示（`data-tippy-content`）也在此列。

### 5.6 DOM 遍历与观察器

- `SKIP_TAGS = SCRIPT/STYLE/TEXTAREA/CODE/PRE/NOSCRIPT/OPTION`；
- `walk(root)`：TreeWalker（SHOW_TEXT|SHOW_ELEMENT）+ 属性翻译；文本节点长度 > 400 直接跳过（性能与安全）；
- `MutationObserver`（`documentElement`，subtree/childList/characterData/attributes）：
  - `childList` 新增节点 → `walk`；
  - `characterData` → `translateTextNode`；
  - `attributes` → `translateAttrs`；
- 启动时 `walk` 一次 + `setTimeout(scanAll, 1500/4000)` 补扫（Vue 懒渲染/异步加载）；
- 已知限制：Vue 重渲染会**覆盖我们改过的文本节点**，需要 observer 再翻一次；这也是“先英文后中文”闪烁的来源（正常现象）。

### 5.7 对外接口（v1.1.11 新增）

- `window.__AFCN_TRANSLATE__(text)`：暴露 `translateValue`，供 `search.js` 做整段翻译（源力石页面）。
- `window.__AFCN__`：防重复注入标记。
- 控制台日志：`[AlecaFrame-ZH] translated nodes=… entries=…`。

## 6. 中文搜索层（`src/search.js`，1138 行）

### 6.1 索引（`buildIndex`）


## 7. 专项实现

### 7.1 裂罅（Riven）

- 属性文本是**整串单节点**（`v-html="stat.description"`），例如 `+109.9% Critical Damage`；引擎用「百分比 + 属性名」规则翻译；

- 负号有 Unicode 变体（`− – — －`），规则统一转 ASCII `-`；
- 裂罅上架 WFM 400：诊断日志（`showErrorToast` 包装）打印实际属性与价格；实测中文下带熔接词条也能上架（此前 400 判断为 WFM 连接瞬断）。

### 7.2 WFM（warframe.market）界面

- 界面文案（`List on warframe.market`、`Edit warframe.market listing`、`75% match`、`Whisper`、`avail.`、`Invisible`、`Create alert`、`Compare live market listings` 等）在 `extra-11.tsv`；
- 品牌名（`warframe.market`、`riven.market`）保留英文；
- 相似裂罅标题/按钮由模板拼接（`'View ' + color.name + ' shards'` 类），靠规则或整段翻译处理。

### 7.3 源力石页面（v1.1.11 专项，坑最多）

**数据源**：插件方法 `GetArchonShardOverview` 返回 JSON（颜色/效果/战甲槽位），效果文本字段为 `regular`/`tauforged`（纯文本）与 `regularHtml`/`tauforgedHtml`（带内联伤害图标 `<img alt="Toxin">`）。

**问题**：
1. 效果指南表格用 `v-html`，图标把句子切成多个文本节点；逐节点翻译会先把元素名（`Toxin`→`毒素`）翻掉，导致整句再也匹配不上 → 半英半中；
2. 战甲卡片的效果摘要（`5 Casting speed`、`+1 more effects`）与 `5 / 5 installed, 3 Tauforged` 是模板拼接/多节点，逐节点同样翻不干净。

**方案**（`src/engine.js` + `src/search.js` 协作）：
1. 引擎在 `translateTextNode` 中**跳过**这些区域，交给整段翻译：
   ```js
   node.parentElement.closest(".archonEffectRow p, .archonRecipeCard p, .archonDetailSlot p,
                              .archonFrameCard small, .archonFrameEffects span, .archonFrameEffects small")
   ```
2. `search.js` 的 `translateArchonComposite()`：
   - `archonCellText(el)`：遍历子节点重建文本，`<img>` 用 `alt/title` 还原英文元素名（`+2 Health on damaging enemies with Toxin`），从而命中 `extra-12.tsv` 的整句词条；
   - 命中后 `el.textContent = 中文`（**图标会被去掉**，这是刻意的取舍）；
   - 触发：`MutationObserver`（80ms 防抖）+ 3 秒兜底轮询（替代早期 1.5s 轮询，减少闪烁）；
   - 摘要规则：`N + 英文效果名` → `N 个 中文效果名`（如 `5 Casting speed` → `5 个 技能施放速度`）。
3. **防循环守卫（血泪教训）**：v1.1.11 开发中曾把「N + 效果名」规则写成无限叠加（`5 个 X` 每轮再加 ` 个`），卡片刷出满屏重复文字。当前守卫：
   - 文本**不含拉丁字母**（已是中文）直接跳过；
   - 只有「数字 + 英文名」且 `translateValue` 确实返回不同中文时才替换。

**词条**：`dict/extra-12.tsv`（128 行）：54 条效果文本 + 26 条效果名 + 6 种颜色 + 6 条特性 + 界面文案；译名依据官方中文 wiki（执刑官源力石页面）与游戏内效果表。

### 7.4 交易历史（未解决，重构时勿踩）

- 统计页数据来自 **AlecaFrame 服务器**：`https://stats.alecaframe.com/api/stats/<userIdentifier>`（`stats.js:675`），不是本地计算；
- 插件方法 `IsTradeHistoryEnabled()` 在非英文游戏语言下返回 `false`，`stats.js:664` 据此显示「仅当游戏语言为英语时可用」；
- **实测**：强制放行该开关后，中文下完成交易，服务器 `trades` 仍为 0，且 `OnTradeFinishedNotification` 事件不触发 → 插件在中文语言下**根本不做交易日志解析/上传**；
- 结论：仅绕过 UI 门禁无效；要做只能自建记录器（解析 EE.log 交易段或截图 OCR），属于新子系统，需单独立项（`docs/待改进清单.md` 有评估）。

- OCR 协议（端口/端点/全局名）是与 MIOEU 脚本的硬契约，改名前先确认所有脚本；

## 10. 坑与教训（重构前必读）

### 10.1 词典/构建层

1. **`extra-*.tsv` 排序**：按字典序会错（`extra-10` < `extra-2` < `extra-9`），必须数字排序，否则新词条“不生效”。
2. **同键多层覆盖**：`items.tsv`（游戏数据，权威但最早写入）会被 `vendor/fixes/extra` 覆盖；发现“游戏官方名被机翻覆盖”时优先查 `fixes.tsv` / `extra-*.tsv`。
3. **上游机翻污染**：`translations.zh-CN.json` 有大量机翻错误，例如：
   - `"Duviri:": "杜维里："`（应「双衍王境：」）→ 已用 `fixes.tsv` 覆盖；
   - `"MR:": "先生："`（MR 被当 Mr.）→ 已用 `fixes.tsv` 覆盖为「段位：」；
   - `Atragraph` 等专名。
   新增词条前先 `grep` 各层，避免“改了没反应/被覆盖”。
4. **多义键**：`Cold` 同时出现在 `extra-5`（天气「寒冷」）与 `extra-7`（伤害类型「冰冻」）；按数值顺序 `extra-7` 覆盖 → 全局「冰冻」，裂罅上下文再补「伤害」。改单义键会误伤另一处，必要时按上下文（裂罅类名）区分。
5. **TSV 格式**：一行 `英文<TAB>中文`，不要空行/多余空格；含 Tab 或换行的文案要转义/拆分。
6. **构建产物不入库**：CI 不依赖产物；新机器 clone 后必须 `python src/build.py`，否则 `bin/alecaframe-zh-cn.js` 不存在（源码构建需要 Python；普通用户走 Release zip）。
7. **BOM**：所有 `*.ps1` 必须 UTF-8 BOM（CI 与 verify 检查）；`bin/ocr/afzh-items.js` 是 `.js` 不要 BOM。

### 10.2 翻译引擎层

1. **只做精确匹配**：`translateValue` 不做模糊/词形变化；文本被模板拆开（Vue 插值、`v-html` 图标）就匹配不到 → 需要规则或整段翻译。
2. **半翻译污染**：逐节点翻译会先把单词翻掉（`Toxin`→`毒素`），导致整句再也匹配不上 → 遇到 v-html/拼接文本，**先跳过节点翻译，再整段处理**（源力石页面的做法）。
3. **文本长度上限 400**：超长文本不翻（性能保护）。
4. **Vue 重渲染覆盖**：翻译后的文本会被 Vue 重绘还原成英文，必须靠 MutationObserver 再翻（闪烁正常）；纯 `textContent` 修改也可能被覆盖。
5. **属性/提示**：`title`、`placeholder`、`aria-label`、`data-tooltip`、`data-tippy-content` 都要翻，否则悬停/搜索框残留英文。
6. **规则要窄**：全局 `RULES` 是每段文本都试，宽正则（如 `^(\d+) (.+)$`）会误伤大量文本；页面专属规则应放局部扫描。
7. **防循环**：任何“替换后可能再次匹配”的规则都要守卫（不含拉丁字母跳过、替换前后不同才写），否则 MutationObserver 会指数级叠加（源力石“满屏个”事故）。
8. **品牌/人名**：`warframe.market`、`riven.market`、`Zaw`、节点名等按约定保留英文；战甲名目前**刻意保留英文**（README FAQ），但战甲卡片上的小字/效果需要翻译。
9. **上下文判定**：裂罅类名检测是“祖先 class 含 riven，最多 8 层”，DOM 结构变化会失效；伤害类型补「伤害」只在裂罅上下文做，避免把普通界面的「火焰」翻成「火焰伤害」。

### 10.3 中文搜索层

1. **反向索引混入 UI 术语**：`Death -> 死亡` 导致输入「死亡」被改写为英文 `Death`；正确策略是**本地过滤优先**，只有本地 0 命中才回退英文查询。
2. **100 条上限**：铸造厂 `showAll=false` 只回 100 条（`type=all` 时实测 100 vs 813），必须强制 `showAll/includeAll`。
3. **赋能页旁路**：赋能页不走 `getFilteredInventory`，是 Vue 侧对 `this.items` 的英文子串过滤 → 必须挂 `receiveArcaneProgress`。
4. **钩子窗口差异**：`main.html` 与 `background.html` 的 `plugin.get()` 是两个对象，钩子要各自装；`whenPluginReady` 轮询 60s，宿主方法改名/版本升级会导致钩子全失效（`__AFZH_SEARCH__` 可查）。
5. **参数形态差异**：`getFilteredInventory(query, includeAll, receive)` vs `GetRivenWeapons(searchString, cb)`（纯字符串）——包装时不能假设都是 JSON。
6. **遗物奖励不在遗物条目里**：需要 `relic-rewards.tsv` 索引，否则部分中文（奖励名）搜不到。
7. **中文部分匹配**：支持「死亡」「暴击」这类部分词；同时要处理部件后缀（`Prime 枪管蓝图`）与精炼度后缀（`Axi A1 完好`）。

### 10.4 宿主/注入层

1. **Overwolf 校验绕过参数**：`--ow-disable-features=extension-validation,read-opk-from-memory` + `--ow-enable-features=force-validation-report-only`；Overwolf 升级可能失效（`HashMismatch`/应用打不开），先 Restore 再 Start。
2. **版本目录变化**：扩展目录按 `<version>/`（如 3.0.6）；升级后启动器自动取最新并重新快照，旧快照保留。
3. **文件占用**：必须先 `Stop-Overwolf` 再改写页面/脚本，否则写失败或被还原。
4. **快照幂等**：每次 Start 先从官方源还原，再注入；`Test-CurrentFilesPristine` 用于判断是否已注入。
5. **git/环境**：本机 git 不在 PATH（用 GitHub Desktop 自带）、`schannel` 证书问题（用 openssl 后端）、系统 Python 是 WindowsApps 桩（用 bundled python）。
6. **PowerShell 5.1 解析**：中文脚本丢 BOM 会解析报错；`verify.ps1` 已内置 BOM + 语法检查。

### 10.5 交易历史

- 数据在服务器端，插件在非英文语言下不解析/上传交易日志；绕过 UI 门禁无数据；要实现需新子系统（见 7.4）。

### 10.6 发布/版本

- `VERSION` 必须与 `CHANGELOG` 首个 `## vX.Y.Z` 一致；
- tag 必须形如 `v1.1.10`，CI 才触发 release；
- 发布包排除 `state/logs/.tools`，用户升级时保留自己的 `state/`、`logs/`；
- 诊断包可能含用户名，回传前提示用户检查。

### 10.7 已知技术债（重构候选）

| 债 | 说明 |
|---|---|
| 启动器单文件 911 行 | 快照/注入/OCR/状态/诊断全部耦合；建议拆模块 + 单元测试 |
| `search.js` 1138 行单文件 | 索引/查询/各类钩子/诊断/测试导出混杂；建议拆 `index`、`hooks`、`query`、`diagnostics` |
| 词典键值模型 | 只有英文→中文精确映射，缺 i18n key；同形异义靠 extra 顺序覆盖，脆弱 |
| 规则与词库混用 | `RULES` 越加越多，难测试；建议规则表 + 每条落测试 |
| DOM 翻译性能 | 每次 mutation 全树 walk + 多次补扫；可做节点级脏标/按页面启用 |
| 状态文件无 schema | `last-session.json`、settings 建议加 `schemaVersion` + 校验 |
| 测试覆盖 | 仅搜索纯函数 49 项；引擎规则/源力石整段翻译无测试（可加 jsdom 或纯函数导出） |
| 文档与代码同步 | 本文与 `docs/*.md` 需随改动更新 |

## 11. 重构建议（目标架构）

### 11.1 建议拆分

```
launcher/            启动器（PS 模块）
  Snapshot.psm1      官方文件快照/还原
  Patch.psm1         页面注入/还原（幂等）
  Overwolf.psm1      进程/flag/加载等待
  Ocr.psm1           OCR 生命周期（可选）
  Cli.ps1            Action 分发 + 状态/诊断

runtime/
  engine/            翻译引擎
    dict.js         词典索引（精确/小写/复合）
    rules.js         规则表（可单测，纯函数）
    dom.js           遍历/观察器/属性
    context.js       裂罅等上下文判定
  search/
    index.js         正向/反向索引、部件/精炼度
    query.js         中文→英文候选、本地过滤
    hooks.plugin.js  插件方法包装
    hooks.app.js     应用级钩子
    diagnostics.js   状态/日志
  shards/            源力石整段翻译（可独立成模块）

dict/
  layers/…           TSV 分层（不变）
```

### 11.2 接口草案（建议）

- `engine.translate(text, ctx?) -> string|null`（纯函数，可单测）
- `engine.scan(root, { skipSelectors, rules })`
- `search.buildIndex(dict) -> { forward, reverse }`
- `search.filter(list, query, nameFields) -> items`
- `hooks.installPlugin(native, { windowKind })` / `hooks.installApp(app)`
- `launcher.patch(pages, scriptTag)` / `launcher.restore(pages)`

### 11.3 迁移顺序（低风险→高风险）

1. 提取纯函数（`translateValue` 规则、`query` 索引）→ 加单测 → 行为不变；
2. `engine.js` 拆模块，构建脚本按模块拼接（bundle 仍是单文件）；
3. `search.js` 拆 index/query/hooks，钩子安装改为配置表；
4. 源力石整段翻译独立模块（目标选择器/规则表可配置）；
5. 启动器拆 PS 模块（先封装 Snapshot/Patch，再加测试）；
6. OCR 保持原样（与主链路解耦），最后动。

### 11.4 验收标准

- `python src/build.py` 产物字节级/行为级等价（词典合并结果 diff 为空）；
- `scripts/verify.ps1 -Package` 全绿；
- `tests/search.test.mjs` 49 项全过 + 新增引擎规则测试；
- 真机回归：Start / Restore / Refresh / Toggle 各一次；中文搜索（仓库/铸造厂/赋能/遗物规划器）；裂罅详情与相似裂罅；源力石三页；统计页。

## 13. 附录

### A. 词典层优先级（低 → 高）

```
items.tsv → mioeu-terms.tsv → vendor/translations.zh-CN.json → fixes.tsv → extra-1 … extra-12（数字升序）
```

### B. 规则速查（易错）

- 百分比/数值：`+109.9% Critical Damage` → `+109.9% 暴击伤害`（裂罅上下文补「伤害」）
- 正负号：`+Multishot` / `-Zoom` / `−Recoil`（Unicode 负号）→ `+多重射击` / `-变焦` / `-后坐力`
- 秒：`6s Combo Duration` → `6 秒连击持续时间`
- 匹配度：`75% match` → `75% 匹配`；`Tauforged Crimson` → `深红 TAU源力石`
- 源力石摘要：`5 Casting speed` → `5 个 技能施放速度`；`+1 more effects` → `另有 1 种效果`
- 融合行：`100 Stela, 5 possible now` → `100 虚空石块，当前可用 5 次`

### C. 钩子清单

**插件级**：`getFilteredInventory`、`getFilteredFoundry`、`getFilteredRelicPlanner`、`GetFilteredUnveiledRivensInfo`、`GetRivenWeapons`、`GetWFMarketSearchSuggestions`、WFM 订单/契约方法。
**应用级**：`relicPlannerApp.receiveUpdate`、`buySellPanelApp.updateSearchSuggestions/suggestionClicked`、`inventoryApp.receiveArcaneProgress`、`showErrorToast`（裂罅上架诊断）。
**页面注入**：10 个 `main/background/AFBuilds/InGameNotification/relicOverlay/relicRecommendation/rivenOverlay/SquadMakingMain/SquadMakingSquad/tradeFinishedNotification` html。
